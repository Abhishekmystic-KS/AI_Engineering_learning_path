PRODUCTION SECRETS

LOCAL DEVELOPMENT

Use a local `.env` file or a developer secret store. Keep it ignored by Git and share only the variable names through `.env.example`.

CI/CD PIPELINES

Store deployment values in the CI/CD platform's encrypted secrets settings. Inject them only into the job that needs them.

CLOUD PRODUCTION

Use a dedicated secret manager instead of plain files on a server.

| Service | Secret Manager |
|---|---|
| AWS | AWS Secrets Manager or Systems Manager Parameter Store |
| Google Cloud | Secret Manager |
| Microsoft Azure | Key Vault |
| Kubernetes | Kubernetes Secrets with encryption and access controls |
| General infrastructure | HashiCorp Vault |

PRODUCTION RULES

- Never hardcode production secrets in application code.
- Never share one secret across every environment.
- Restrict who and what can read each secret.
- Audit secret access.
- Rotate secrets without exposing them in deployment logs.
- Use short-lived credentials when possible.
- Remove unused keys and old team access.
- Back up secret configuration safely, not by copying raw values into Git.
